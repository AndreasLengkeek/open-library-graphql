# 02.2 Codegen for resolver types

## Goal
Every subgraph's resolvers are typed from its `schema.graphql`, and the build fails if the generated types are stale.

## Notes
- Packages: `@graphql-codegen/cli`, `@graphql-codegen/typescript`, `@graphql-codegen/typescript-resolvers`.
- In each service's `codegen.ts`, set `federation: true` so `__resolveReference` and the federation directives are understood.
- Set `contextType` to the service's `Context` type, which will hold `viewer`, loaders and the database later.
- Use `mappers` to map GraphQL types to your database row or Open Library DTO types, so parent types are honest.
- Add scripts:
  - `pnpm codegen` generates types for all services.
  - `pnpm codegen:check` regenerates them and fails if `git diff --exit-code` reports a change. CI uses this in 06.3.
- Retrofit the users resolvers from 02.1 to use the generated `Resolvers` type.

## Acceptance criteria
- [x] `pnpm codegen` produces `src/__generated__/resolvers-types.ts` (or similar) in each service.
- [x] Changing a field type in `services/users/schema.graphql` without regenerating makes `pnpm codegen:check` fail, and regenerating makes `tsc` point at the resolver that's now wrong.
- [x] No `any` in resolver signatures.

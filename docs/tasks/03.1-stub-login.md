# 03.1 Stub sign-up and log-in

## Goal
The `users` subgraph issues signed JWTs through `signUp` and `logIn`.

## Notes
- **This is a development stub and is NOT SECURE.** `logIn(username)` returns a token for any existing username with no password. Put that warning in the schema description too.
- Sign HS256 tokens with `JWT_SECRET` (`jose` is a good library). Claims: `sub` = User id, `iat`, `exp` (for example 7 days).
- `signUp` fails with `BAD_USER_INPUT` if the username is taken.
- Put signing and verification in a small shared workspace package (for example `packages/auth`), so all three subgraphs verify tokens the same way.

## Acceptance criteria
- [ ] `signUp` then `logIn` return a token. Decoding it (for example on jwt.io) shows the User id as `sub`.
- [ ] Tests cover a duplicate username, an unknown username on `logIn`, and an expired token being rejected by the verify function.

## Concepts practised
JWT basics · a shared workspace package across subgraphs · mutations in a subgraph

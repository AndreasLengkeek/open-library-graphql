# 01.4 Design review with Claude

## Goal

Get your design challenged before any resolver code depends on it, then record the final ownership decisions as an ADR.

## How

Start a session with Claude (for example `/grill-with-docs`). Share `docs/design/entity-map.md` and the three schemas, and ask for a review against the checklist below. Change the design where the review finds problems, re-run `pnpm compose`, and repeat until there's nothing left to fix.

## Review checklist

- **Ownership:** every field has exactly one sensible owner. Nothing is `@shareable` without a reason.
- **Keys:** the key fields are stable and cheap to resolve. A subgraph only adds a reference resolver when it can actually resolve the entity.
- **No hidden subgraph calls:** no resolver needs data from another subgraph unless it goes through the router.
- **Nullability:** an unknown Book doesn't fail the whole `me` query. Lists are non-null where an empty list means something.
- **Domain fit:** names match the glossary. Status Shelves vs Custom Shelves follows ADR 0002. Review and Rating follow the domain rules.
- **Mutations:** consistent return shapes. Ownership is checkable: everything owned is addressed by id.
- **Query plans:** for `MyShelves` and `BookDetail`, predict the order the router visits subgraphs, and how many times.
- **Evolvability:** how hard would S1 (splitting `reviews` out of `library` with `@override`) be with this design?

## Acceptance criteria

- [x] The review session happened, and every finding is either fixed or explicitly accepted with a reason.
- [x] `docs/adr/0003-entity-ownership.md` records the final entity map in a few sentences: which types are entities, who owns each key, and the one or two decisions you'd most want a future reader to understand.
- [x] `pnpm compose` still passes.

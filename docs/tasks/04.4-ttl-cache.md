# 04.4 TTL cache and results

## Goal
Add a short in-memory cache across requests for Open Library responses, measure it separately from DataLoader, and write up the results.

## Notes
- DataLoader caches **within one request**. This cache lives **across requests**.
- Use a small LRU with a TTL (for example `lru-cache`, 5 minutes), keyed by Work or Author key, sitting under the loaders.
- Think about it: what goes stale? Is it acceptable for Book data from Open Library? (Yes, mostly.) Would it be acceptable for `averageRating`? (No, and that lives in `library` anyway.)
- Optional: compare with HTTP-level caching (`Cache-Control`, or `@cacheControl` plus router response caching). Just document it; don't build it.

- [ ] `docs/perf.md` has a final table: Baseline → DataLoader (Books) → DataLoader (Authors) → TTL cache, for all three scenarios, with request counts and latencies.
- [ ] Turning the cache off with an env flag (`OPEN_LIBRARY_CACHE=off`) brings back the 04.3 numbers.

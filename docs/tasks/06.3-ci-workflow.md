# 06.3 CI workflow

## Goal
A single GitHub Actions workflow that checks every PR and publishes to `@staging` on merge to `main`.

## Notes
- `.github/workflows/ci.yml`. Jobs on `pull_request`:
  - `typecheck`: `pnpm -r exec tsc --noEmit`
  - `test`: `pnpm test` (no network thanks to msw)
  - `codegen-drift`: `pnpm codegen:check`
  - `schema-check`: one `rover subgraph check reading-tracker@staging --name <subgraph> --schema ...` per subgraph (a matrix works well). This catches composition errors and breaking changes against the registry. Operation checks become useful once the router has reported some traffic.
- On `push` to `main`: `rover subgraph publish` for each subgraph, gated on the other jobs passing.
- Store `APOLLO_KEY` as a repository secret. PRs from forks won't have it, so decide how `schema-check` should behave there.
- Install Rover in CI using the official install script, pinned to a version.

## Acceptance criteria
- [ ] A PR that removes a field a client uses fails `schema-check`, and the failure is visible in the PR.
- [ ] A PR that changes the schema without regenerating types fails `codegen-drift`.
- [ ] Merging to `main` publishes, and Studio's changelog shows the change.

## Concepts practised
Schema checks in CI · breaking-change detection · CI-driven publishing

# 05.2 setReadingStatus

## Goal
The Viewer can set, change or clear their Reading Status for a Book.

## Notes
- `setReadingStatus(bookId, status)`: insert or update a row in `reading_status`; `status: null` deletes it.
- It requires a Viewer and only ever touches the Viewer's own row, so ownership comes from the key.
- Validate the `bookId` format (`/^OL\d+W$/`) and nothing more (see SPEC domain rules).
- The return value should let the client update the Status Shelves without fetching again. What does your design return?
- This is where "Finishing a Book" happens (status changes to `READ`). Leave a clear hook for S3, but don't build events yet.

## Acceptance criteria
- [ ] Through the router: set `READING`, change it to `READ`, then clear it. Each step is reflected in `me { shelves }`.
- [ ] Tests cover: no token → `UNAUTHENTICATED`; malformed id → `BAD_USER_INPUT`; a status change moves the Book between Status Shelves.

## Concepts practised
Mutations in a federated graph · mutation return values that keep the client cache current · Viewer-scoped writes

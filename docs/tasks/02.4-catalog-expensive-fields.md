# 02.4 catalog: expensive fields

## Goal

Add the fields that cost an extra Open Library request per entity: `Author.bio`, `Author.birthDate` and `Author.books`.

## Notes

- `Author.bio` and `Author.birthDate`: `GET /authors/<id>.json`. `bio` is either a string or `{ type, value }`, so normalise it. `birth_date` is free text ("13 September 1916"), so keep it as a `String`.
- `Author.books`: `GET /search.json?q=author_key:<id>&limit=<n>`. Cap it.
- Resolve these **lazily** in field resolvers, so a query that doesn't ask for `bio` never fetches it.
- If an Author is reached through a Book, only `id` and `name` are known. That's the point: `bio` must trigger a fetch.

## Acceptance criteria

- [x] `book(id: "OL893414W") { description authors { bio birthDate books { title } } }` returns real data.
- [x] A test proves `searchBooks { title }` makes exactly 1 Open Library request, and asking for `authors { bio }` across 5 results makes 1 + (number of distinct Authors) requests. Write this number down; it's your 04.3 baseline.

## Concepts practised

Field-level resolvers · lazy resolution · the N+1 problem when the upstream API can't batch

# 04.1 Baseline measurement

## Goal
Honest "before" numbers for Open Library request counts and latency, so 04.2–04.4 can show their effect.

## Notes
- Run locally under `rover dev` only. A router connected to GraphOS on the Free plan is capped at 60 requests per minute and would distort the numbers.
- Use the counter from 02.3: expose it through a debug endpoint or log line, and reset it per operation.
- Write `scripts/measure.ts`. It logs in as `andreas`, runs each of these 5 times, and records the Open Library request count plus median and p95 latency:
  1. `MyShelves` (20 Books)
  2. `MyShelves` + `authors { bio }`
  3. `BookDetail` for one Book
- Make sure no caching is in place (SPEC conventions: no cache until 04.4).

## Acceptance criteria
- [ ] `docs/perf.md` has a results table (operation × request count × median × p95) under a "Baseline" heading.
- [ ] You can explain the request count for scenario 1 by referring to the query plan from 03.4.

Measuring before optimising · counting upstream requests · why the N+1 problem appears in federated reference resolvers

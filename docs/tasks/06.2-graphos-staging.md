# 06.2 Publish to GraphOS staging

## Goal
Publish the subgraphs to a GraphOS graph `reading-tracker@staging`, and have a Compose profile that runs the router against GraphOS.

## Notes
- Create a free GraphOS account and a graph. Get a graph API key: that's `APOLLO_KEY`, and `APOLLO_GRAPH_REF=reading-tracker@staging`.
- `rover subgraph publish reading-tracker@staging --name users --schema services/users/schema.graphql --routing-url http://users:4001/graphql` (repeat for each subgraph). The routing URL is what the *router* will call, so use the Compose service names.
- Explore Studio: the schema, the composition result, the changelog.
- Add a Compose profile `graphos`: the router runs with `APOLLO_KEY` and `APOLLO_GRAPH_REF` and **no** `--supergraph`, so it fetches the schema from GraphOS. `docker compose --profile graphos up`.
- On the Free plan, a router connected to GraphOS is **capped at 60 requests per minute**. That's fine for checking things, not for measuring.
- Publish a deliberate change (for example add a field) and watch the GraphOS-connected router pick it up **without a restart**.

## Acceptance criteria
- [ ] Studio shows the composed `@staging` variant with all three subgraphs.
- [ ] `docker compose --profile graphos up` serves `MyShelves` using the schema from GraphOS.
- [ ] A published schema change appears in the running router without a redeploy.

## Concepts practised
Schema registry · variants · `rover subgraph publish` · managed federation (fetching the schema from GraphOS)

# 03.4 Read the query plan

## Goal
Understand exactly what the router does for `MyShelves` and `BookDetail`, and how it handles a Book that doesn't exist.

## Notes
- In Sandbox, open the **Query Plan** panel. Or enable `plugins: { experimental.expose_query_plan: true }` in `router.yaml` and send the header `Apollo-Expose-Query-Plan: true`.
- Write `docs/design/query-plans.md`. For each operation, paste the plan and annotate every `Fetch`, `Flatten`, `Sequence` and `Parallel` node in your own words.
- Compare it with your prediction from 01.4. Where were you wrong?
- Null-Book scenario: the seed put `OL999999999W` on a Custom Shelf. Run `MyShelves`. Does the query still succeed? Where does the `null` appear, and does it spread further up than you intended?

## Acceptance criteria
- [ ] `docs/design/query-plans.md` explains both plans, and how many times the router calls each subgraph.
- [ ] The unknown Book shows up as a `null` at the level your design intended. If not, fix the nullability (go back through 01.4 if it changes the design).

## Concepts practised
Query planning · `_entities` fetches · Flatten paths · null propagation across subgraphs

# 04.2 DataLoader for Books

## Goal
Batch the catalog's Book reference resolver so a shelf of 20 Books costs **one** Open Library request, not 20.

## Notes
- Open Library supports this: `search.json?q=key:(/works/A OR /works/B OR ...)&fields=...`. Check the URL length and request page size for 20 to 100 keys; split into chunks if needed.
- Create a new `DataLoader` per request, in the context function. Never share one across requests. Why does that matter for correctness and for auth?
- The batch function must return results **in the same order as the keys**, with `null` for missing Works.
- `book(id)` and the reference resolver should both use the loader.
- Note that the router already sends all 20 representations in one `_entities` call. Without DataLoader, Apollo calls `__resolveReference` once per representation.

## Acceptance criteria
- [ ] Re-running `scripts/measure.ts` shows scenario 1 at 1 Book request (plus any Author requests). Record it in `docs/perf.md` under "After DataLoader (Books)".
- [ ] A test proves 20 representations lead to 1 HTTP request, missing Works come back as `null`, and the order is preserved.

## Concepts practised
DataLoader batching · per-request loaders · `__resolveReference` with batching · real upstream batch APIs

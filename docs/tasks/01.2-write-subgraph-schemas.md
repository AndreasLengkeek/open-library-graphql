# 01.2 Write the subgraph schemas

## Goal
Turn the entity map into three Federation 2 schemas: `services/users/schema.graphql`, `services/catalog/schema.graphql` and `services/library/schema.graphql`.

## Notes
- Start every file with `extend schema @link(url: "https://specs.apollo.dev/federation/v2.x", import: [...])`, using the current 2.x version. Import only the directives you use.
- Design the whole capability list, including the mutations from M5. Changing the schema later is fine, but designing it now is the point of this milestone.
- Decide on nullability deliberately, especially for cross-subgraph references and lists.
- Decide how mutations return results: the changed object, a payload type, or something else. Be consistent.
- Write a short description string on every type and on every field that isn't obvious.
- Use glossary terms. If you find you need a term that isn't in the glossary, stop and add it first.

## Acceptance criteria
- [ ] Three `.graphql` files exist, each a valid subgraph SDL.
- [ ] Every capability in SPEC.md can be expressed against the combined schema, at least on paper.
- [ ] `docs/design/entity-map.md` matches the SDL. If they disagree, update the map.

## Concepts practised
Federation 2 `@link` · `@key`, `@shareable`, `@external` / `@requires` (if you need them) · schema-first design · nullability as a contract

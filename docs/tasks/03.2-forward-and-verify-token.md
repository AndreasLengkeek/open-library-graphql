# 03.2 Forward and verify the token

## Goal
The router forwards the client's `Authorization` header to every subgraph. Each subgraph verifies it independently and builds `context.viewer`.

## Notes
- `router/router.yaml`:
  ```yaml
  headers:
    all:
      request:
        - propagate:
            named: authorization
  ```
- In each subgraph's `context` function: no header → `viewer: null`; valid token → `viewer: { id }`; invalid or expired token → throw `UNAUTHENTICATED` (or treat it as anonymous; decide which and document it).
- Subgraphs must not trust any other header (such as `x-user-id`) for identity.
- Think about it: the router doesn't verify anything yet. What does that mean if a subgraph is reachable directly? (S6 revisits this.)

## Acceptance criteria
- [ ] Sending `Authorization: Bearer <token>` to the router results in `context.viewer` being set in all three subgraphs. Prove it with a log line or a debug field.
- [ ] Without the header, `viewer` is `null` everywhere.
- [ ] Tests in each subgraph cover the three cases (none, valid, invalid).

## Concepts practised
Router header propagation · authentication in every subgraph · request context

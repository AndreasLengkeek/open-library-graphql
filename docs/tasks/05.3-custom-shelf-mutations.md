# 05.3 Custom Shelf mutations

## Goal
`createShelf`, `renameShelf`, `deleteShelf`, `addToShelf` and `removeFromShelf`, with ownership enforced.

## Notes
- Every mutation that takes a `shelfId` loads the Shelf and checks `shelf.userId === viewer.id`, otherwise `FORBIDDEN`. A missing Shelf → `NOT_FOUND`.
- Targeting a Status Shelf with any of these → `BAD_USER_INPUT` (ADR 0002).
- A duplicate name for the same User → your error convention from 05.1.
- `addToShelf` with a Book already on the Shelf: is that a no-op or an error? Decide, and document it in the schema description.
- `deleteShelf` removes only the Shelf's entries (SPEC domain rules).
- Think about whether `FORBIDDEN` vs `NOT_FOUND` leaks the existence of other Users' Shelves. Shelves are public, so it doesn't matter here, but note when it would.

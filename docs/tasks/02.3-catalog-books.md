# 02.3 catalog subgraph: search and Books

## Goal
A `catalog` subgraph on port 4002 that serves `searchBooks`, `book(id)` and the cheap Book and Author fields from Open Library.

## Notes
- Build a small, typed Open Library client module (`openLibrary.ts`). Every request sends `User-Agent` from `OPEN_LIBRARY_USER_AGENT`. Count the requests it makes (04.1 will use the counter).
- Search: `GET https://openlibrary.org/search.json?q=<query>&limit=<first>&fields=key,title,author_key,author_name,first_publish_year,cover_i,isbn,subject`.
- One Book by id: the same endpoint with `q=key:/works/<id>`. (In 04.2 you'll find that `q=key:(/works/A OR /works/B)` fetches many in one request.)
- Cover URL: `https://covers.openlibrary.org/b/id/<cover_i>-M.jpg`. It's `null` when `cover_i` is missing.
- Strip the `/works/` and `/authors/` prefixes so ids are bare keys (`OL45804W`).
- Author `name` comes from the search document (`author_key` and `author_name` are parallel arrays). No extra request is needed.
- The Book reference resolver is deliberately **naive** here: one HTTP request per Book. Don't optimise it yet.
- Unknown or well-formed-but-missing Work → `null`. Malformed id → `BAD_USER_INPUT`.
- `searchBooks` should cap `first` (for example at 50).

## Acceptance criteria
- [ ] `searchBooks(query: "dune", first: 5)` returns real Books with Authors, from the running server.
- [ ] `book(id: "OL893414W") { title authors { name } }` returns Dune by Frank Herbert.
- [ ] `book(id: "OL999999999W")` returns `null` without an error, and `book(id: "nope")` returns a `BAD_USER_INPUT` error.
- [ ] Tests run against msw fixtures (you can create the first fixtures here; 02.6 expands them), not the network.

## Concepts practised
Wrapping a REST API as a subgraph · DTO → GraphQL mapping · entity reference resolvers backed by HTTP · nullable lookups

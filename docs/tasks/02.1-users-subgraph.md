# 02.1 users subgraph

## Goal
A running `users` subgraph on port 4001 that serves the read side of your users schema from SQLite.

## Notes
- Packages: `@apollo/server`, `@apollo/subgraph`, `graphql`, `graphql-tag`, `drizzle-orm`, `better-sqlite3`, plus `drizzle-kit` as a dev dependency.
- `buildSubgraphSchema({ typeDefs, resolvers })`, loading `typeDefs` from `schema.graphql` so the file stays the source of truth.
- Use Drizzle for the table definitions and generate migrations with `drizzle-kit`. Credentials aren't needed (the log-in stub has no password), so don't add columns for them.
- Implement the User reference resolver (`__resolveReference`) and `user(username)`.
- `me` can return `null` for now; authentication arrives in M3.
- Use `startStandaloneServer` or Express. Either is fine.

## Acceptance criteria
- [x] `pnpm --filter users dev` starts the server on `:4001`.
- [x] `query { user(username: "x") { id } }` returns `null` for an unknown user, without an error.
- [x] A Vitest integration test inserts a User into a temporary or in-memory database and resolves it through both `user(username)` and an `_entities` query (the representation the router would send).

## Concepts practised
`buildSubgraphSchema` · `__resolveReference` · the `_entities` and `_service` fields · Drizzle with SQLite

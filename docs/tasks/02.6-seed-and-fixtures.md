# 02.6 Seed data and test fixtures

## Goal
A repeatable dataset for manual runs and measurements, and recorded Open Library fixtures so tests never touch the network.

## Notes
- `pnpm seed` resets and fills `users.db` and `library.db`, writing directly to each subgraph's database with its own Drizzle schema:
  - 3 Users (for example `andreas`, `sam`, `kai`).
  - For `andreas`: **20 real Work keys** spread across the three Status Shelves, plus a "Favourites" Custom Shelf holding 5 of them. Pick Books with several co-authors and Books sharing an Author (for example two Tolkien Books), so de-duplication has something to show in M4.
  - One deliberately unknown but well-formed id (`OL999999999W`) on a Custom Shelf, for the null-Book scenario in 03.4.
  - A handful of Reviews from different Users on overlapping Books.
- Fixtures: a script (`pnpm fixtures:record`) that fetches the Open Library responses the tests need and saves them under `services/catalog/test/fixtures/`. The msw handlers serve them; any unmatched request fails the test.

## Acceptance criteria
- [ ] Running `pnpm seed` twice leaves the same data (it's idempotent).
- [ ] `pnpm test` passes with networking disabled.
- [ ] The seed's Work keys are listed in one place (for example `seed/books.ts`) so 04.1 can reuse them.

## Concepts practised
Test isolation from third-party APIs · msw · seed data that demonstrates edge cases

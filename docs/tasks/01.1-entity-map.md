# 01.1 Entity map on paper

## Goal
Before writing any SDL, decide how the domain is split across `users`, `catalog` and `library`. Record it in `docs/design/entity-map.md`.

## What to decide
For every type in the [glossary](../../GLOSSARY.md) and every capability in [SPEC.md](../../SPEC.md#capabilities):
1. **Is it an entity?** Can more than one subgraph contribute fields to it, or refer to it?
2. **Who owns its `@key`, and what are the key fields?** Does any type need more than one key?
3. **Who contributes which fields?** For example, which subgraph resolves `Book.title`? Which resolves `Book.averageRating`? And `User.shelves`?
4. **Which subgraphs only *reference* an entity** (a stub with just the key) rather than contributing fields to it? Should that type be marked `resolvable: false`?
5. **Value types vs entities:** is a Shelf an entity? Is a Review? What about the Reading Status enum?
6. **Where does each root field live?** `me`, `searchBooks`, `book`, `user`, and every mutation.

## Questions to work through
- How is `Book.reviews` resolved when `library` only stores `bookId`? Sketch the steps the router takes.
- `me { shelves { books { title } } }`: list each subgraph the router has to visit, in order.
- How do you represent a Book that Open Library doesn't know about (an unknown `bookId` stored in `library`)? What does that mean for nullability?
- Status Shelves aren't stored anywhere (see [ADR 0002](../adr/0002-reading-status-is-not-a-shelf.md)). What is their `id`? Is it stable?
- Is `Review.user` an entity reference? Which subgraph resolves `displayName` on it?

## Acceptance criteria
- [ ] `docs/design/entity-map.md` has a table with columns for type, entity (yes/no), key fields, owner, and contributing subgraphs and fields.
- [ ] Every capability in SPEC.md maps to the subgraph that owns its root field.
- [ ] The "questions to work through" are each answered in a sentence or two.

## Concepts practised
Entities vs value types · `@key` ownership · contributed fields · reference-only stubs · thinking in query plans before writing code

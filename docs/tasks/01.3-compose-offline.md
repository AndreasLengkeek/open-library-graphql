# 01.3 Compose offline

## Goal

Prove the three schemas compose into a supergraph, without running any servers.

## Notes

- Create `router/supergraph.yaml`:
  ```yaml
  federation_version: =2.x.y # pin the version
  subgraphs:
    users: { routing_url: http://localhost:4001/graphql, schema: { file: ../services/users/schema.graphql } }
    catalog: { routing_url: http://localhost:4002/graphql, schema: { file: ../services/catalog/schema.graphql } }
    library: { routing_url: http://localhost:4003/graphql, schema: { file: ../services/library/schema.graphql } }
  ```
- Run `APOLLO_ELV2_LICENSE=accept rover supergraph compose --config router/supergraph.yaml > router/supergraph.graphql`. This doesn't need a GraphOS account.
- Read every composition error and hint carefully. Each one is a federation lesson.
- Add a `pnpm compose` script for this command.
- Open the generated `supergraph.graphql` and find the `join__type` and `join__field` directives. They show which subgraph resolves what.

## Acceptance criteria

- [x] `pnpm compose` exits 0 with no errors.
- [x] Any composition _hints_ are either fixed, or have a one-line note in `docs/design/entity-map.md` saying why you left them.
- [x] You can point to the `join__field` lines for `Book.title`, `Book.averageRating` and `User.shelves` and explain them.

## Concepts practised

Supergraph composition · `rover supergraph compose` · reading `join__*` directives · composition errors vs hints

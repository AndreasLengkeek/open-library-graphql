# 05.1 Error conventions

## Goal
One shared way to raise `UNAUTHENTICATED`, `FORBIDDEN`, `BAD_USER_INPUT` and `NOT_FOUND`, used by every subgraph, before writing any mutations.

## Notes
- Add helpers to the shared package from 03.1 (for example `forbidden(message)` → `GraphQLError` with `extensions.code`).
- Add a `requireViewer(context)` helper that throws `UNAUTHENTICATED` if there's no Viewer.
- Decide whether expected business errors (a duplicate Shelf name) should be **thrown errors** or **typed results** (a union of payload and error types). Record the choice. If it changes the SDL, take it back through review.
- Check what the router does with subgraph errors: does `extensions.code` reach the client unchanged? Does the `path` make sense?

## Acceptance criteria
- [ ] The helpers are used by at least one existing resolver, with tests.
- [ ] A short "Errors" section in SPEC.md or `docs/design/` documents the convention.

## Concepts practised
GraphQL error design · errors vs result types · how errors travel through the router
